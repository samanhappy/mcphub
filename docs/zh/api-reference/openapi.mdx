# OpenWebUI 集成的 OpenAPI 生成

MCPHub 现在支持从 MCP 工具生成 OpenAPI 3.0.3 规范，实现与 OpenWebUI 和其他 OpenAPI 兼容系统的无缝集成，无需 MCPO 作为中间代理。

## 功能特性

- ✅ **自动 OpenAPI 生成**：将 MCP 工具转换为 OpenAPI 3.0.3 规范
- ✅ **OpenWebUI 兼容**：无需 MCPO 代理的直接集成
- ✅ **实时工具发现**：动态包含已连接 MCP 服务器的工具
- ✅ **双参数支持**：支持 GET（查询参数）和 POST（JSON 正文）进行工具执行
- ✅ **按范围授权**：使用 MCP Bearer Key 的权限范围控制工具发现和执行
- ✅ **完整元数据**：具有适当模式和文档的完整 OpenAPI 规范

## API 端点

### OpenAPI 规范

<CodeGroup>

```bash GET /openapi/openapi.json
curl -H "Authorization: Bearer $MCPHUB_KEY" "http://localhost:3000/openapi/openapi.json"
```

```bash GET /openapi/openapi.yaml
curl -H "Authorization: Bearer $MCPHUB_KEY" "http://localhost:3000/openapi/openapi.yaml"
```

```bash 带参数
curl -H "Authorization: Bearer $MCPHUB_KEY" "http://localhost:3000/openapi/openapi.json?title=我的 MCP API&version=2.0.0"
```

</CodeGroup>

生成并返回所有已连接 MCP 工具的完整 OpenAPI 3.0.3 规范。`.json` 和 `.yaml` 版本接受相同的查询参数。

**查询参数：**

<ParamField query="title" type="string" optional>
  自定义 API 标题
</ParamField>

<ParamField query="description" type="string" optional>
  自定义 API 描述
</ParamField>

<ParamField query="version" type="string" optional>
  自定义 API 版本
</ParamField>

<ParamField query="serverUrl" type="string" optional>
  自定义服务器 URL
</ParamField>

<ParamField query="servers" type="string" optional>
  要包含的服务器名称列表（逗号分隔）
</ParamField>

### 组/服务器特定的 OpenAPI 规范

<CodeGroup>

```bash GET /openapi/:name/openapi.json
curl -H "Authorization: Bearer $MCPHUB_KEY" "http://localhost:3000/openapi/mygroup/openapi.json"
```

```bash GET /openapi/:name/openapi.yaml
curl -H "Authorization: Bearer $MCPHUB_KEY" "http://localhost:3000/openapi/mygroup/openapi.yaml"
```

```bash 带参数
curl -H "Authorization: Bearer $MCPHUB_KEY" "http://localhost:3000/openapi/myserver/openapi.json?title=我的服务器 API&version=1.0.0"
```

</CodeGroup>

为特定组或服务器生成并返回 JSON 或 YAML 格式的 OpenAPI 3.0.3 规范。如果存在具有给定名称的组，则返回该组中所有服务器的规范。否则，将名称视为服务器名称并仅返回该服务器的规范。

**路径参数：**

<ParamField path="name" type="string" required>
  组 ID/名称或服务器名称
</ParamField>

**查询参数：**

与主 OpenAPI 规范端点相同（title、description、version、serverUrl、servers）。

### 可用服务器

<CodeGroup>

```bash GET /api/openapi/servers
curl "http://localhost:3000/api/openapi/servers"
```

</CodeGroup>

返回已连接的 MCP 服务器名称列表。

<ResponseExample>

```json 示例响应
{
  "success": true,
  "data": ["amap", "playwright", "slack"]
}
```

</ResponseExample>

### 工具统计

<CodeGroup>

```bash GET /api/openapi/stats
curl "http://localhost:3000/api/openapi/stats"
```

</CodeGroup>

返回有关可用工具和服务器的统计信息。

<ResponseExample>

```json 示例响应
{
  "success": true,
  "data": {
    "totalServers": 3,
    "totalTools": 41,
    "serverBreakdown": [
      {"name": "amap", "toolCount": 12, "status": "connected"},
      {"name": "playwright", "toolCount": 21, "status": "connected"},
      {"name": "slack", "toolCount": 8, "status": "connected"}
    ]
  }
}
```

</ResponseExample>

### 工具执行

<CodeGroup>

```bash GET /openapi/tools/{serverName}/{toolName}
curl -H "Authorization: Bearer $MCPHUB_KEY" "http://localhost:3000/openapi/tools/amap/maps_weather?city=Beijing"
```

```bash POST /openapi/tools/{serverName}/{toolName}
curl -H "Authorization: Bearer $MCPHUB_KEY" -X POST "http://localhost:3000/openapi/tools/playwright/browser_navigate" \
  -H "Content-Type: application/json" \
  -d '{"url": "https://example.com"}'
```

</CodeGroup>

规范通过 `servers[0].url` 声明工具执行的基础地址。分组或服务器的基础地址是 `/openapi/:name`，工具请求使用 `/openapi/:name/tools/{serverName}/{toolName}`。

**路径参数：**

<ParamField path="serverName" type="string" required>
  MCP 服务器的名称
</ParamField>

<ParamField path="toolName" type="string" required>
  要执行的工具名称
</ParamField>

## OpenWebUI 集成

要将 MCPHub 与 OpenWebUI 集成：

<Steps>
  <Step title="启动 MCPHub">
    确保 MCPHub 正在运行，并且已配置 MCP 服务器
  </Step>
  <Step title="获取 OpenAPI 规范">
    ```bash
    curl -H "Authorization: Bearer $MCPHUB_KEY" http://localhost:3000/openapi/openapi.json > mcphub-api.json
    curl -H "Authorization: Bearer $MCPHUB_KEY" http://localhost:3000/openapi/openapi.yaml > mcphub-api.yaml
    ```
  </Step>
  <Step title="添加到 OpenWebUI">
    在 OpenWebUI 中导入 OpenAPI 规范文件或直接指向 URL
  </Step>
</Steps>

## 生成的 OpenAPI 结构

生成的 OpenAPI 规范包括：

### 工具转换逻辑

- **简单工具**（≤10 个原始参数）→ 带查询参数的 GET 端点
- **复杂工具**（对象、数组或 >10 个参数）→ 带 JSON 请求正文的 POST 端点
- **所有工具**都包含完整的响应模式和错误处理

### 生成操作示例

```yaml
/tools/amap/maps_weather:
  get:
    summary: "根据城市名称或者标准adcode查询指定城市的天气"
    operationId: "amap_amap-maps_weather"
    tags: ["amap"]
    parameters:
      - name: city
        in: query
        required: true
        description: "城市名称或者adcode"
        schema:
          type: string
    responses:
      '200':
        description: "Successful tool execution"
        content:
          application/json:
            schema:
              $ref: '#/components/schemas/ToolResponse'
```

### 安全性

启用 Bearer 鉴权时，规范和工具调用均需发送 `Authorization: Bearer <key>`。分组 Key 可用于授权分组入口。服务器 Key 可用于授权服务器入口，或成员均已获授权的分组入口。排除范围同时作用于规范和调用。个人 Key 还受所有者当前可访问的分组和服务器约束。

对于新的集成，请在 OpenWebUI 中使用 Dashboard 复制的 `/openapi/:name` 基础地址和相应的 Key。旧版 `/api` 规范及工具接口已弃用，仍按 Dashboard API 的现有规则鉴权，使用 Bearer Key 时需要系统级全访问 Key。`/api/openapi/servers` 和 `/api/openapi/stats` 仍是 Dashboard 接口。

## 故障排除

<AccordionGroup>
  <Accordion title="OpenAPI 规范显示没有工具">
    确保 MCP 服务器已连接。检查 `/api/openapi/stats` 查看服务器状态。
  </Accordion>

  <Accordion title="工具执行失败">
    验证工具名称和参数是否与 OpenAPI 规范匹配。检查服务器日志以获取详细信息。
  </Accordion>

  <Accordion title="OpenWebUI 无法连接">
    确保 MCPHub 可从 OpenWebUI 访问，并且 OpenAPI URL 正确。
  </Accordion>

  <Accordion title="规范中缺少工具">
    检查您的 MCP 服务器配置中是否启用了工具。确认当前 Key 有权访问该工具。
  </Accordion>
</AccordionGroup>
