# OpenAPI Generation for OpenWebUI Integration

MCPHub now supports generating OpenAPI 3.0.3 specifications from MCP tools, enabling seamless integration with OpenWebUI and other OpenAPI-compatible systems without requiring MCPO as an intermediary proxy.

## Features

- ✅ **Automatic OpenAPI Generation**: Converts MCP tools to OpenAPI 3.0.3 specification
- ✅ **OpenWebUI Compatible**: Direct integration without MCPO proxy
- ✅ **Real-time Tool Discovery**: Dynamically includes tools from connected MCP servers
- ✅ **Dual Parameter Support**: Supports both GET (query params) and POST (JSON body) for tool execution
- ✅ **Scoped Access**: Uses MCP bearer-key scopes for tool discovery and execution
- ✅ **Comprehensive Metadata**: Full OpenAPI specification with proper schemas and documentation

## API Endpoints

### OpenAPI Specification

<CodeGroup>

```bash GET /openapi/openapi.json
curl -H "Authorization: Bearer $MCPHUB_KEY" "http://localhost:3000/openapi/openapi.json"
```

```bash GET /openapi/openapi.yaml
curl -H "Authorization: Bearer $MCPHUB_KEY" "http://localhost:3000/openapi/openapi.yaml"
```

```bash With Parameters
curl -H "Authorization: Bearer $MCPHUB_KEY" "http://localhost:3000/openapi/openapi.json?title=My MCP API&version=2.0.0"
```

</CodeGroup>

Generates and returns the complete OpenAPI 3.0.3 specification for all connected MCP tools. The `.json` and `.yaml` variants accept the same query parameters.

**Query Parameters:**

<ParamField query="title" type="string" optional>
  Custom API title
</ParamField>

<ParamField query="description" type="string" optional>
  Custom API description
</ParamField>

<ParamField query="version" type="string" optional>
  Custom API version
</ParamField>

<ParamField query="serverUrl" type="string" optional>
  Custom server URL
</ParamField>

<ParamField query="servers" type="string" optional>
  Comma-separated list of server names to include
</ParamField>

### Group/Server-Specific OpenAPI Specification

<CodeGroup>

```bash GET /openapi/:name/openapi.json
curl -H "Authorization: Bearer $MCPHUB_KEY" "http://localhost:3000/openapi/mygroup/openapi.json"
```

```bash GET /openapi/:name/openapi.yaml
curl -H "Authorization: Bearer $MCPHUB_KEY" "http://localhost:3000/openapi/mygroup/openapi.yaml"
```

```bash With Parameters
curl -H "Authorization: Bearer $MCPHUB_KEY" "http://localhost:3000/openapi/myserver/openapi.json?title=My Server API&version=1.0.0"
```

</CodeGroup>

Generates and returns the OpenAPI 3.0.3 specification for a specific group or server in JSON or YAML format. If a group with the given name exists, it returns the specification for all servers in that group. Otherwise, it treats the name as a server name and returns the specification for that server only.

**Path Parameters:**

<ParamField path="name" type="string" required>
  Group ID/name or server name
</ParamField>

**Query Parameters:**

Same as the main OpenAPI specification endpoint (title, description, version, serverUrl, servers).

### Tool Execution

<CodeGroup>

```bash GET /openapi/tools/{serverName}/{toolName}
curl -H "Authorization: Bearer $MCPHUB_KEY" "http://localhost:3000/openapi/tools/amap/maps_weather?city=Beijing"
```

```bash POST /openapi/tools/{serverName}/{toolName}
curl -H "Authorization: Bearer $MCPHUB_KEY" -X POST "http://localhost:3000/openapi/tools/playwright/browser_navigate" \
  -H "Content-Type: application/json" \
  -d '{"url": "https://example.com"}'
```

</CodeGroup>

The specification declares the base URL for tool execution in `servers[0].url`. For a group or server, this is `/openapi/:name`, and requests use `/openapi/:name/tools/{serverName}/{toolName}`.

Decimal numeric strings are converted in full, including scientific notation (for example, an integer parameter of `1e3` becomes `1000`). Fractional values for integer parameters, non-finite values, and invalid strings are left unchanged for the tool's schema validation; they are not truncated into a different number. Already numeric values are forwarded unchanged.

String array items submitted by the dashboard are converted according to the tool's `items.type` (`integer`, `number`, or `boolean`) before being forwarded to the MCP server.

**Path Parameters:**

<ParamField path="serverName" type="string" required>
  The name of the MCP server
</ParamField>

<ParamField path="toolName" type="string" required>
  The name of the tool to execute
</ParamField>

## OpenWebUI Integration

To integrate MCPHub with OpenWebUI:

<Steps>
  <Step title="Start MCPHub">
    Ensure MCPHub is running with your MCP servers configured
  </Step>
  <Step title="Get OpenAPI Specification">
    ```bash
    curl -H "Authorization: Bearer $MCPHUB_KEY" http://localhost:3000/openapi/openapi.json > mcphub-api.json
    curl -H "Authorization: Bearer $MCPHUB_KEY" http://localhost:3000/openapi/openapi.yaml > mcphub-api.yaml
    ```
  </Step>
  <Step title="Add to OpenWebUI">
    Import the OpenAPI specification file or point to the URL directly in OpenWebUI
  </Step>
</Steps>

## Generated OpenAPI Structure

The generated OpenAPI specification includes:

### Tool Conversion Logic

- **Simple tools** (≤10 primitive parameters) → GET endpoints with query parameters
- **Complex tools** (objects, arrays, or >10 parameters) → POST endpoints with JSON request body
- **All tools** include comprehensive response schemas and error handling

### Example Generated Operation

```yaml
/tools/amap/maps_weather:
  get:
    summary: "根据城市名称或者标准adcode查询指定城市的天气"
    operationId: "amap_amap-maps_weather"
    tags: ["amap"]
    parameters:
      - name: city
        in: query
        required: true
        description: "城市名称或者adcode"
        schema:
          type: string
    responses:
      '200':
        description: "Successful tool execution"
        content:
          application/json:
            schema:
              $ref: '#/components/schemas/ToolResponse'
```

### Security

When bearer authentication is enabled, send `Authorization: Bearer <key>` for both specification requests and tool calls. Group keys can use their authorized group routes. Server keys can use their authorized server routes or groups whose members are all authorized. Exclusions apply to both the specification and execution. Personal keys also respect their owner's current access to groups and servers.

For new OpenWebUI integrations, copy the `/openapi/:name` base URL from the dashboard and configure the corresponding key. The deprecated `/api` specification and tool routes retain dashboard authentication, which requires a system-level all-access key when using bearer keys. `/api/openapi/servers` and `/api/openapi/stats` remain dashboard endpoints.

## Troubleshooting

<AccordionGroup>
  <Accordion title="OpenAPI spec shows no tools">
    Ensure MCP servers are connected. Check `/api/openapi/stats` for server status.
  </Accordion>

  <Accordion title="Tool execution fails">
    Verify the tool name and parameters match the OpenAPI specification. Check server logs for details.
  </Accordion>

  <Accordion title="OpenWebUI can't connect">
    Ensure MCPHub is accessible from OpenWebUI and the OpenAPI URL is correct.
  </Accordion>

  <Accordion title="Missing tools in specification">
    Check if tools are enabled in your MCP server configuration. Verify that the key can access the tool on the selected route.
  </Accordion>
</AccordionGroup>
