---
title: "Skills over MCP"
description: "Import and publish multi-file Agent Skills on MCPHub endpoints."
---

Administrators can publish [Agent Skills](https://agentskills.io/specification) through MCPHub using the [MCP Skills Extension](https://skills.extensions.modelcontextprotocol.io/specification/beta/skills). Remote discovery and loading require a client that supports the extension on MCP 2026-07-28. The client reads the Skill over MCP, so no files are installed into the agent's local environment by MCPHub.

## Import and publish

1. Open **Skills** in the dashboard as an administrator.
2. Select a local folder containing `SKILL.md`, or enter a public GitHub directory URL such as `https://github.com/owner/repo/tree/main/skill-name`. Use a commit SHA or URL-encode the slashes in a branch or tag name.
3. Select **Enabled** and choose the publication scope. **Global endpoint** publishes to `/mcp` if global routing is enabled. Selected groups publish to their group endpoints and apply the existing route authentication and group visibility.
4. Connect a compatible client to the published endpoint. It discovers Skills via `skills/list`, fetches their manifests via `skills/get`, and reads individual files via `resources/read`.

The directory name must match the `name` in `SKILL.md`. Import supports up to 512 regular files and 16 MiB of file content per Skill. GitHub imports resolve the source to a commit at import time. **Replace files** imports a new snapshot under the same Skill URI and publication scope. Turn off **Enabled** or delete the Skill to take it off the published endpoints.

For the TypeScript SDK, create the client with `versionNegotiation: { mode: "auto" }` so it discovers the 2026-07-28 endpoint.

## Storage and compatibility

Skill snapshots are stored next to the settings file in its `.skills` sidecar directory. Include the sidecar in backups and mount the parent directory for Docker persistence. The catalog is available in single-instance self-hosted deployments with either settings backend.

Both the manifest and its SHA-256 digests describe the original UTF-8 or binary file bytes. If a Skill changes between fetching a manifest and reading a file, clients can refresh the manifest and verify the new file. Existing tools, prompts, and resources remain available through their usual methods.
